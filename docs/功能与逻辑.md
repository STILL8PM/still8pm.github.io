# 功能与逻辑

## 应用启动流程

```text
document/index.html
        ↓
src/main.jsx
        ↓
React.StrictMode
        ↓
App.jsx
        ↓
HashRouter + WorkbenchProvider + Layout
        ↓
Nav + 当前路由页面
```

`WorkbenchProvider` 在应用装配时创建请求客户端、GitHub 数据源和认证服务，
并刷新后台会话与仓库状态。后台地址未配置时，状态为 `not-configured`，页面
正常展示但不发起工作台后台请求。

## 当前页面功能

| 页面 | 路由 | 当前职责 |
| --- | --- | --- |
| 首页 | `/#/` | 展示原有个人介绍和站点内容 |
| 工作台 | `/#/workbench` | 展示后台、仓库和会话基础状态 |
| Vue 文档 | `/#/vued` | iframe 展示 Vue 文档 |
| React 文档 | `/#/reactd` | iframe 展示 React 文档 |
| 其他文档 | `/#/other` | 展示文档树占位结构 |
| 个人信息 | `/#/about` | 请求并展示一言接口内容 |

## 工作台状态流转

```text
启动
 ├─ 未配置后台 → not-configured → 展示等待配置
 └─ 已配置后台 → loading
                  ├─ 会话、仓库请求均成功 → ready
                  ├─ 两个请求均失败 → error → 展示重试
                  └─ 一个成功、一个失败 → ready，保留成功结果
```

## 数据写入流程

```text
页面业务模块
    ↓ 调用 工作台数据源
统一请求客户端
    ↓ 携带 HttpOnly 会话
Serverless 后端
    ↓ 校验身份、权限、版本号
GitHub Contents API
    ↓
目标仓库中的 JSON/Markdown 数据文件
```

写入必须带当前版本号或文件 SHA。版本不一致时返回冲突，页面提示重新加载或
合并，禁止静默覆盖其他终端的数据。

## 非工作台旧功能

个人信息页仍使用原有第三方一言接口。开发环境由 `vite.config.js` 的 `/api`
代理转发，生产环境使用页面中配置的第三方地址；这条链路与工作台后台地址
`VITE_WORKBENCH_API_BASE_URL` 分开，不能混用。
