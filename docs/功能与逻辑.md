# 功能与逻辑

## 应用启动流程

```text
document/index.html
        ↓
src/main.jsx
        ↓
React.StrictMode
        ↓
App.jsx
        ↓
HashRouter + WorkbenchProvider + Layout
        ↓
登录、注册或受保护的后台页面
```

`WorkbenchProvider` 在应用装配时创建请求客户端、通用存储服务和认证服务，
并刷新后台会话与存储状态。后台地址未配置时，状态为 `not-configured`，页面
正常展示但不发起工作台后台请求。

## 当前页面功能

| 页面 | 路由 | 当前职责 |
| --- | --- | --- |
| 管理员登录 | `/#/login` | 使用管理员账号密码建立后台会话 |
| 注册账号 | `/#/register` | 创建普通账号并返回登录页 |
| 管理控制台 | `/#/admin/dashboard` | 查看系统概况和最近活动 |
| 模块功能 | `/#/admin/modules` | 以树形结构管理前台模块、功能和展示状态 |
| 用户管理 | `/#/admin/users` | 管理用户账号、状态、角色和分组 |
| 角色管理 | `/#/admin/roles` | 管理角色及其权限 |
| 分组管理 | `/#/admin/groups` | 管理用户分组 |
| 权限管理 | `/#/admin/permissions` | 管理权限标识 |
| 系统设置 | `/#/admin/settings` | 配置后台和数据存储提供商 |

## 工作台状态流转

```text
启动
 ├─ 未配置后台 → not-configured → 展示等待配置
 └─ 已配置后台 → loading
                  ├─ 会话、存储状态请求均成功 → ready
                  ├─ 两个请求均失败 → error → 展示重试
                  └─ 一个成功、一个失败 → ready，保留成功结果
```

## 数据写入流程

```text
页面业务模块
    ↓ 调用 Storage Service
统一请求客户端
    ↓ 携带 HttpOnly 会话
Serverless 后端
    ↓ 校验身份、权限、版本号
Storage Adapter
    ├─ GitHub Contents API
    └─ Nutstore WebDAV
    ↓
目标存储中的 JSON/Markdown 数据文件
```

写入必须带当前版本号、文件 SHA 或 ETag。版本不一致时返回冲突，页面提示重新加载或
合并，禁止静默覆盖其他终端的数据。

## 当前界面边界

根地址和未知地址统一进入登录页。访问任意 `/admin/*` 路由时必须先从后端取得
有效会话，并确认用户包含 `role-admin` 管理员角色；否则立即返回登录页。账号
密码只提交给配置的 Serverless 后端，不保存到 Local Storage。后续前台功能
将由模块功能配置驱动后逐步增加。

## 后台管理能力

- 仪表盘：根据当前数据计算用户、模块、功能和系统状态，并展示最近审计操作。
- 模块功能：新增、编辑、显示、隐藏、删除和排序模块及其功能，以树形结构展示父子关系。
- 前台显示规则：模块和功能均为显示状态且满足登录或权限条件时才会展示；隐藏模块会隐藏全部子功能，重新显示模块不会改变子功能各自的状态。
- 用户管理：搜索、新增、编辑、启停、删除以及分配角色和分组。
- 角色管理：新增、编辑、删除角色并分配权限；系统内置角色禁止删除。
- 分组管理：新增、编辑、删除分组并分配角色；存在用户引用时禁止删除。
- 权限管理：新增、编辑、删除权限；存在角色引用时禁止删除。
- 审计日志：记录所有本地管理动作，支持查看和清空。
- 系统设置：配置站点、默认分组、注册开关以及 GitHub/WebDAV 存储。
- 数据迁移：管理数据支持 JSON 导出、导入和恢复默认值。

## 本地持久化

Serverless 后台未部署时，管理数据保存在浏览器 Local Storage 的
`workbench.admin.data.v2`。本地数据不包含密码、Token 或 WebDAV 应用密码。
首次读取旧版 `workbench.admin.data.v1` 时会将原 `content` 集合自动迁移为默认模块下的
功能记录。导入支持 v1 和 v2 备份，校验并迁移后自动追加审计日志。
