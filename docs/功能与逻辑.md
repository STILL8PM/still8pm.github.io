# 功能与逻辑

## 应用启动流程

```text
document/index.html
        ↓
src/main.jsx
        ↓
React.StrictMode
        ↓
App.jsx
        ↓
HashRouter + WorkbenchProvider + Layout
        ↓
Nav + 当前路由页面
```

`WorkbenchProvider` 在应用装配时创建请求客户端、GitHub 数据源和认证服务，
并刷新后台会话与仓库状态。后台地址未配置时，状态为 `not-configured`，页面
正常展示但不发起工作台后台请求。

## 当前页面功能

| 页面 | 路由 | 当前职责 |
| --- | --- | --- |
| 管理控制台 | `/#/admin/dashboard` | 查看系统概况和最近活动 |
| 内容管理 | `/#/admin/content` | 管理前台功能入口和展示状态 |
| 用户管理 | `/#/admin/users` | 管理用户账号、状态、角色和分组 |
| 角色管理 | `/#/admin/roles` | 管理角色及其权限 |
| 分组管理 | `/#/admin/groups` | 管理用户分组 |
| 权限管理 | `/#/admin/permissions` | 管理权限标识 |
| 系统设置 | `/#/admin/settings` | 查看后台和 GitHub 数据配置 |

## 工作台状态流转

```text
启动
 ├─ 未配置后台 → not-configured → 展示等待配置
 └─ 已配置后台 → loading
                  ├─ 会话、仓库请求均成功 → ready
                  ├─ 两个请求均失败 → error → 展示重试
                  └─ 一个成功、一个失败 → ready，保留成功结果
```

## 数据写入流程

```text
页面业务模块
    ↓ 调用 工作台数据源
统一请求客户端
    ↓ 携带 HttpOnly 会话
Serverless 后端
    ↓ 校验身份、权限、版本号
GitHub Contents API
    ↓
目标仓库中的 JSON/Markdown 数据文件
```

写入必须带当前版本号或文件 SHA。版本不一致时返回冲突，页面提示重新加载或
合并，禁止静默覆盖其他终端的数据。

## 当前界面边界

旧首页、文档页、个人信息页和旧导航已经移除。当前前端只承载后台管理界面，
后续前台功能将由内容管理配置驱动后逐步增加。
