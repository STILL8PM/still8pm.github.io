# 路由与部署

## 路由规则

应用使用 `HashRouter`，页面地址必须带 `#`：

```text
https://still8pm.github.io/#/
https://still8pm.github.io/#/workbench
```

不要直接改为 `BrowserRouter`，除非同时配置 GitHub Pages 的 404 回退和资源
路径策略，否则刷新子页面可能返回 404。

## 构建配置

文件：`document/vite.config.js`

- `base: "./"`：适配仓库站点和自定义域名。
- `build.outDir: "build"`：保持原有 gh-pages 发布目录。
- `/api` 开发代理：只服务旧的一言接口。

## 常用命令

在 `document/` 目录执行：

```bash
npm install
npm run dev
npm run build
npm run preview
npm run deploy
```

Windows PowerShell 若禁止执行 `npm.ps1`，使用 `npm.cmd` 替代，例如：
`npm.cmd run build`。

## 环境变量

参考 `document/.env.example`：

- `VITE_WORKBENCH_API_BASE_URL`
- `VITE_GITHUB_REPOSITORY_OWNER`
- `VITE_GITHUB_REPOSITORY_NAME`
- `VITE_GITHUB_REPOSITORY_BRANCH`
- `VITE_GITHUB_DATA_ROOT`

Vite 会把 `VITE_` 变量打包进前端，因此这些变量只能放公开配置，不能放 Secret。

## 发布检查

1. 确认 `npm run build` 成功。
2. 确认输出目录为 `document/build/`。
3. 确认构建产物中没有 Token、Secret 或本地路径。
4. 确认 `/#/` 和 `/#/workbench` 均可打开并刷新。
5. 确认 Serverless 后端允许 GitHub Pages 域名跨域访问。
6. 再执行 `npm run deploy` 发布 `gh-pages` 分支。
